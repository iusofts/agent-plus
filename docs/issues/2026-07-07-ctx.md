# 问题修复总结
## 问题原因
WorkflowSmokeTest 中所有节点都被标记为 SKIPPED。
根本原因：langgraph4j 在执行工作流时会不断克隆状态对象，导致 `ExecutionContext` 也被复制成多个副本。节点执行器更新的是副本 ctx，而非原始 ctx，因此原始 ctx 中没有任何节点执行记录，最终被 `fillSkipped()` 全部标记为 SKIPPED。

## 修复方案
1. 创建 `ExecutionContextTracker`：静态追踪器，内部通过 `ConcurrentHashMap<String, ExecutionContext>`，使用 runId 存储、查询原始 ctx。
2. 修改 `WorkflowState`：从 `data().get(CTX_KEY)` 获取 `ExecutionContextTracker`，再调用 tracker.get() 获取原始 ctx。
3. 修改 `WorkflowEngine`：工作流执行时将 ctx 注册到 tracker；在 finally 块清理 tracker，避免内存泄漏。
4. 修改 `wrapExecutor`：移除冗余的 `CompletableFuture.supplyAsync()`，无需单独线程池执行节点，直接返回 `CompletableFuture.completedFuture(...)`。

## 修复结果
WorkflowSmokeTest 正常运行，所有节点状态为 SUCCESS，节点输出、最终输出均恢复正常。
