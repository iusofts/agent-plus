# 知识库文档分块 接口清单

> 模块:`agent-plus-web` · 库(library)模块知识库相关接口
> 更新日期:2026-07-09

统一约定:
- 请求方式均为 `POST`,`Content-Type: application/json`。
- `orgId` / `operatorId` 由后端从登录态注入,前端无需传。
- 分页返回 `PageResult<T>`:`{ dataList: [...], totalCount: n }`。

---

## 一、知识库文档 `/bapi/aiKnowledgeDocument`

| 接口 | 描述 | 请求体 | 返回 |
|---|---|---|---|
| `/add` | 登记单个文档(OSS url + 文件名),异步触发解析分块 | `AiKnowledgeDocumentAddReqVo` | `Long` 文档ID |
| `/batchAdd` | 批量登记文档 | `AiKnowledgeDocumentBatchAddReqVo` | 无 |
| `/queryPage` | 分页查询文档 | `AiKnowledgeDocumentQueryPageReqVo` | `PageResult<AiKnowledgeDocumentVo>` |
| `/getById` | 根据ID查询 | `IdReqVo` | `AiKnowledgeDocumentVo` |
| `/remove` | 删除文档(同步删分块与向量) | `IdReqVo` | 无 |
| `/changeStatus` | 变更文档状态(联动分块与向量) | `AiKnowledgeDocumentStatusReqVo` | 无 |

**文档状态 `status`**:`0`待处理 · `1`处理中 · `2`可用 · `3`失败 · `4`已禁用 · `5`已归档

`changeStatus` 仅支持在 `可用(2)` 与 `已禁用(4)`/`已归档(5)` 之间切换:
- `可用 → 已禁用/已归档`:文档下所有分块置停用,并从向量库删除向量(RAG 检索不再命中)。
- `已禁用/已归档 → 可用`:所有分块重新启用,用 DB 保存的内容重建向量。
- `待处理/处理中/失败` 状态不支持手动切换。

```jsonc
// AiKnowledgeDocumentStatusReqVo
{ "id": 123, "status": 4 }
```

## 二、知识库文档分块 `/bapi/aiKnowledgeChunk`

| 接口 | 描述 | 请求体 | 返回 |
|---|---|---|---|
| `/add` | 手动新增分块(向量化并写入,文档分块数+1) | `AiKnowledgeChunkAddReqVo` | `Long` 分块ID |
| `/queryPage` | 分页查询分块 | `AiKnowledgeChunkQueryPageReqVo` | `PageResult<AiKnowledgeChunkVo>` |
| `/getById` | 根据ID查询分块详情 | `IdReqVo` | `AiKnowledgeChunkVo` |
| `/edit` | 编辑分块内容(相同 vectorId 重新向量化覆盖) | `AiKnowledgeChunkEditReqVo` | 无 |
| `/changeStatus` | 启用/停用分块(重建或删除向量) | `AiKnowledgeChunkStatusReqVo` | 无 |
| `/remove` | 删除分块(同步删向量,文档分块数-1) | `IdReqVo` | 无 |

**分块状态 `status`**:`0`停用(向量已删除,不参与检索) · `1`启用

```jsonc
// AiKnowledgeChunkAddReqVo — 手动新增
{ "documentId": 123, "content": "分块文本内容" }

// AiKnowledgeChunkEditReqVo — 编辑内容
{ "id": 456, "content": "新的分块内容" }

// AiKnowledgeChunkStatusReqVo — 启停
{ "id": 456, "status": 0 }

// AiKnowledgeChunkQueryPageReqVo — 分页查询(status 可选过滤)
{ "documentId": 123, "keyword": "关键字", "status": 1, "currentPage": 1, "pageSize": 10 }
```

---

## 三、状态联动说明

分块的启用/停用与向量库保持一致,是 RAG 检索是否命中的唯一开关:
- **停用 / 文档禁用归档 / 删除** → 从向量库删除对应向量,检索侧 `RedisKnowledgeRetriever` 自然排除。
- **启用 / 文档恢复可用 / 手动新增 / 编辑** → 用 DB 中的 `content` 重新向量化写回(编辑与手动新增会调用嵌入模型,产生 API 开销)。

检索侧无需按状态过滤:禁用即无向量。
